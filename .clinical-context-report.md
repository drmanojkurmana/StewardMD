## Output shape
`assembleClinicalContext(sccmBundle, opts = {})` ->
```
{
  patient: { id, sex, age, birthDate? } | null,
  activeProblems:     [ { code, system, text, onset? } ],            // most-recent first
  currentMedications: [ { drug, code, dose?, route? } ],
  allergies:          [ { substance, code, reaction?, criticality? } ],
  recentAbnormalLabs: [ { code, text, value, unit, flag, effective } ], // most-recent first, capped
  recentEncounters:   [ { type, date, reason? } ],                    // most-recent first, capped
  keyProcedures:      [ { code, text, system?, date? } ],             // present iff bundle carries them
  diagnosticReports:  [ { code, text, status, effective, conclusion? } ],
  summary: "62F. 4 active problems, 2 current meds, 2 allergies, 2 abnormal labs."
}
```
Aligned with the downstream MaiK-egress shape (`maik-context.js`, unchanged): SCCM-only, text-first labels,
no vendor/provenance/source ids cross over. Optional (`?`) fields are attached only when the source carries a
value — never emitted as fabricated placeholders.

`opts`: `maxLabs`=20, `maxEncounters`=10, `maxProcedures`=20, `maxReports`=20 (defaults); `asOf` overrides the
age/recency reference (defaults to `bundle.meta.generatedAt`).

## How abnormal labs are detected (two independent mechanisms, per spec)
1. **Explicit interpretation flag** — `observation.interpretation` present and not "normal"/"N". Faithfully
   normalized to a short `flag` (high->H, low->L, short codes like HH/LL/POS preserved, else "A").
2. **Out-of-range value** — numeric `value.value` compared against `referenceRange.low/high`; below low -> L,
   above high -> H.
Abnormal if either fires; `flag` prefers the explicit interpretation, else the derived range direction. Only
`category === "laboratory"` observations are considered (vitals excluded); in-range + "N"-flagged excluded.

## No-fabrication guard (the load-bearing property)
The module only STRUCTURES what is already in the record. It makes NO clinical decision and NO recommendation.
Every emitted value is either copied verbatim from a source field or a faithful derivation of one:
- `age` = deterministic UTC whole-years from `birthDate` as-of `generatedAt` (null if either missing — no
  invented age);
- `flag` = normalized interpretation / range direction (a marker, not a copied clinical value);
- `summary` = COUNTS ONLY + demographics, no findings.
Two tests enforce it: (a) every clinical string in the output (problem text/code, med drug/code, allergy
substance, lab text/value/unit, report conclusion, procedure) must appear verbatim in `JSON.stringify(source)`;
(b) a minimal bundle yields zero clinical text and a summary that matches no diagnosis/dose regex.

## Defensiveness / bounding
- Missing/null/`{}`/partial/`{conditions:"not-an-array"}` bundles never throw -> empty arrays + safe summary
  ("Patient. 0 active problems, ..."). Null-safe accessors throughout, plus a top-level try/catch fallback.
- Every raw resource list is sliced to `HARD_CAP=5000` before any sort/map (no unbounded work on a hostile
  bundle); output lists are then capped by the `opts` maxima.
- No input mutation (does not call the mutating `validate.js`); pure and side-effect-free.

## Concerns / notes
- **Procedures aren't in SCCM v1** (`RESOURCE_KEYS` has no Procedure). `keyProcedures` reads `bundle.procedures`
  defensively (future-proof) and is `[]` for real SCCM bundles today. If/when SCCM adds a Procedure resource,
  wire it in the normalizer and this passes through unchanged.
- **`opts.asOf`/`generatedAt` drives age + recency.** With neither present, `age` is null (never invented) and
  undated items sort last (stable original order). This keeps the function fully deterministic (no wall clock).
- **`maik-context.js` intentionally untouched** (per task). This assembler is the richer, doctor-facing
  structuring layer; feeding its result into that egress path is a follow-up wiring task, gated by the existing
  sandbox/egress guards.
- Fallback policy for ambiguous status is "show, don't hide": a Condition with absent/unknown clinicalStatus,
  and a Medication with absent/unknown status, surface (only explicitly resolved/stopped/completed are dropped).
  This is a safety-conservative default; if the owner prefers strict active-only, tighten `CONDITION_ACTIVE` /
  `MED_NOT_CURRENT`.

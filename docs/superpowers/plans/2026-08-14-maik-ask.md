# MaiK Ask — implementation plan

Design: `docs/superpowers/specs/2026-08-14-maik-ask-design.md`. Flag `smd_maik_ask` (default OFF).
Reversible: every phase is additive + flag-gated; nothing changes the existing Scribe → SMD_NLP → EMR
pipeline. Recovery point (tag/branch) before Phase C. Each phase ships with tests and is independently
mergeable behind the flag.

**Golden rule:** the pathway engine decides WHAT to ask; the LLM only decides HOW to word it. No phase
lets the LLM invent the interview or execute unvalidated output.

---

## Phase A — Inspect + provider abstraction (no behaviour change)
- Re-confirm the reuse map in the design against current code (`SMD_VOICE.listen`, `whisperModel`,
  `SMD_AI.extract`, `applyVoice`/`_voiceMerge`/`VOICE_MAP`, `st.assessVals`/`assessTouched`).
- Create `maik-reasoning.js` (`SMD_MAIK_REASON`) with `GeminiVertexProvider` stubs
  (`generateNextQuestion`/`extractPatientAnswer`/`detectLanguage`) that call **existing** `SMD_AI`
  (no new server kinds yet — return a fixed stub so the interface is exercisable).
- **Done when:** interface exists, is unit-testable with a mock provider, and imports cleanly; zero
  change to Scribe behaviour.

## Phase B — Clinical pathway engine
- `maik-pathways.js` (`SMD_PATHWAYS`): pure `match / nextTarget / isComplete / knownFrom`.
- `clinical-pathways/headache.json` + `fever.json` + `cough.json` first (schema §4.1). Mark others TODO.
- Extend `VOICE_MAP` (additive) with any new pathway→EMR field keys.
- **Tests:** `maik-ask-pathways.test.mjs` — match by complaint text (EN/TE), `nextTarget` returns the
  highest-priority *unknown* field, `knownFrom(assessVals)` seeds correctly so known fields aren't asked.
- **Done when:** given `{complaint:"headache", duration:"3 days", location:"right"}`, nextTarget skips
  duration+location and returns severity/character/etc.; `isComplete` respects required + maxQuestions.

## Phase C — "✦ Let MaiK Ask" UI + permission gate  *(recovery point before this)*
- Button in the OPD-EMR assessment/Voice-Consult panel (shown only when `smd_maik_ask` on AND a
  complaint is known). Confirm sheet (Start/Cancel). Live patient card + doctor controls
  (Pause/Stop/Skip/Ask manually/Return). `maik-ask.css` (reuse `motion.css` tokens).
- No LLM/TTS/ASR yet — wire the UI state machine with scripted stub questions.
- **Tests:** `_render` smoke (button appears only under flag+complaint; confirm sheet; Stop always
  present). **Done when:** the interview UI opens/closes/steps on stubs without touching the EMR.

## Phase D — Structured question generation (Gemini/Vertex)
- Add server kinds `maik-ask-next` in `functions/api/ai/[[path]].js`, prompts in
  `functions/api/ai/_maik-ask.js` (mirror `_opd-scribe.js`: strict "ONLY JSON", `parseJsonLoose`,
  `sanitizeMaikNext` validating `action ∈ {ask,clarify,finish,alert_doctor}`, `targetField ∈ pathway`).
  Optionally set `responseMimeType:"application/json"` for this kind only.
- `GeminiVertexProvider.generateNextQuestion` posts the **minimum** ctx (complaint, pathway, target,
  known, language profile). Client validates before use; invalid → retry once → predefined pathway Q.
- **Tests:** `maik-ask-extract.test.mjs` (prompt + sanitizer): rejects unknown action/targetField;
  falls back on invalid JSON. **Done when:** a target field yields one natural, validated question.

## Phase E — Patient answer extraction
- Deterministic first: run `SMD_VVITALS`/`SMD_EMRMAP` (+ number-words) on the answer transcript.
- Only if ambiguous/empty → server kind `maik-ask-extract` (`sanitizeMaikExtract`: findings must be
  explicitly stated, values typed, confidence ∈ [0,1], field ∈ pathway). Never infer.
- **Tests:** EN/TE/TE-EN/Hinglish answer samples → correct `{field,value,confidence}`, no invented
  findings. **Done when:** "Right side lo undi, nausea undi" → `location=right-sided, nausea=present`.

## Phase F — Native TTS
- Add `@capacitor-community/text-to-speech`; `cap sync`. `speak({text, lang})` with te-IN/hi-IN/en-IN
  map + graceful fallback (available voice → on-screen). Web = on-screen only.
- **Tests:** unit-test the lang map + fallback selection (mock plugin). **Done when:** the question is
  spoken on device (manual) and never crashes when a voice is missing.

## Phase G — Connect findings to the existing EMR
- Fold extracted findings through `applyVoice(updates)` → `_voiceMerge` (doctor-guard). Extend the
  update record + `_voiceMerge` (additive) to carry `source:"patient_spoken_via_MaiK"` + `confidence`
  + `timestamp` per field, WITHOUT changing existing merge behaviour for other sources.
- **Tests:** finding fills the mapped `assessVals` key; a doctor-touched field is **not** overwritten;
  source tag present. **Done when:** interview answers appear in the real EMR fields, doctor value wins.

## Phase H — Review + doctor override
- Review screen ("N asked / M updated" + new patient-reported history + Review/Continue). Save via the
  existing assessment flow. **Tests:** review lists exactly the fields MaiK filled; edits persist over
  MaiK values. **Done when:** doctor can review, edit, and save; nothing auto-saves.

## Phase I — Safety + red-flag handling
- Red-flag detection from findings → "⚠ Possible important finding [Review]", stop routine questioning,
  hand to doctor. Enforce the §9 MUST-NOTs at the provider boundary (no diagnose/treat/reassure).
- **Tests:** a red-flag answer triggers the alert + stop, never a diagnosis; forbidden actions rejected.
- **Done when:** the safety matrix passes; no path emits diagnosis/treatment to the patient.

## Phase J — Multilingual / code-switch tests
- Full §39 matrix (EN/TE/TE-EN/Hinglish/TE-HI-EN) across language handling, extraction, next-question,
  no-duplicate, target field, source, confidence, EMR mapping. **Done when:** matrix green.

## Phase K — Offline ASR + online reasoning integration
- End-to-end demo-mode run (§38 scripted patient) of the §40 headache walkthrough on device: local ASR
  + native TTS + Gemini reasoning, DEMO-labelled, never saved unless chosen. **Done when:** the full
  loop runs start→review in demo mode.

## Phase L — Benchmark before local LLM
- Measure Gemini/Vertex quality + latency + cost on the pathway set. **Only then** consider a
  `QwenLocalProvider` (Qwen3-0.6B Q4_K_M) behind the SAME `SMD_MAIK_REASON` interface. **Do NOT add
  Qwen / any 400–500 MB model in Phases A–K.**

---

## Performance / cost targets
- Question gen < ~2 s where possible; ASR near real-time; TTS starts speaking quickly; process the
  answer immediately after the utterance. Subtle "Thinking…" only when a real LLM call is in flight.
- Phase 1 cost: STT ₹0 (local), TTS ₹0 (native), pathway ₹0 (local); LLM = existing Vertex/Gemini,
  minimized (cached templates, deterministic-first, minimum context). Phase 2 goal: ₹0 via local Qwen.

## Guardrails carried through every phase
- Flag-gated (`smd_maik_ask` OFF) + reversible; existing Scribe/EMR untouched.
- Doctor permission required to start; Stop always available.
- LLM output validated before any action; invalid → predefined pathway question; never execute raw text.
- Findings tagged `patient_spoken_via_MaiK`; never overwrite `assessTouched` fields; never
  `doctor_confirmed` without the doctor.
- No diagnosis / prescription / treatment / investigation / reassurance to the patient — history only.
- Pathway content (red flags) reviewed by the owner-clinician before production.

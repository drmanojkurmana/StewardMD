**Goal:** Close Phase 1 by hardening the as-built Stage-1..5 ABDM machinery against DPDP obligations and the adversarial findings accumulated during Stages 3–5, with NO new protocol surface — only correctness/erasure/accountability fixes + owner-onboarding. Everything runs offline vs the existing mock — no real credentials, no real endpoints.

**Architecture:** Stage 6 is the *hardening* layer that **consumes and surgically corrects** the already-built Stage-1..5 modules — it adds no new crypto, no new gateway calls, no new normalizer. The DPDP purpose-binding is a stamp-then-guard: the engine consume tail tags the CanonicalBundle with the consented `purpose.code`, and the MaiK boundary refuses any use whose purpose differs (no secondary use). The no-PHI sweep is a codebase-audit test + a KV-write guard proving only HMACs/ids/tokens leave the process. The cron wiring reuses the EXISTING `stewardmd-api` Worker `scheduled()` → Pages-Function `X-Admin-Token` delegation pattern (the same shape FollowCare/Updates/watch-lab already use), behind `flagOn(env)`, fail-safe. PHI discipline is unchanged from Stages 3–5: pass-through, ephemeral, the only clinical-at-rest is the transient encrypted R2 buffer (which this stage now provably erases). Pure dependency-injected ES modules over D1 (`env.CONNECT_DB`) + R2 (`env.CONNECT_R2`) + KV (`env.MAIK_KV`, non-PHI only) + the Stage-0 secrets. `fidelius.js`/`gateway.js`/`consent.js`/`normalize.js`/`identity.js` stay functionally as-built (fidelius gets a docstring/contract-only reconciliation).

**Tech Stack:** Plain ES modules, D1, R2, KV, WebCrypto, `node:test`. No new dependencies. ### Task 1 — PIN the `sweep` `expires_at`/`now` type contract (`state.js#sweep`) — **BLOCKING (blocks the Task-8 expiry cron)**

**Files:** Edit `functions/_connect/abdm/state.js` (`sweep` only); Test `test/connect/abdm/sweep-typecontract.test.mjs`.

**Carry-forward source:** [Stage-3 whole-branch, teeth]. As read, `sweep` (state.js:264) computes `const expired = Number(row.expires_at) < Number(now);`. The module header documents `now` as an **ISO string** and every caller passes ISO (`[[path]].js` builds `now: () => new Date().toISOString()`; `putTxn`/`putConsentReq` store `expiresAt` from `consent.expiry`, an ISO/artifact value). `Number("2026-08-01T…")` → `NaN`, and `NaN < NaN` → `false`, so the **expiry branch never fires** → an expired non-terminal txn keeps its sealed ephemeral key + buffer past TTL. This is a silent PHI-lifetime leak and a **blocking correctness bug before any expiry cron is wired**.

**Interfaces:**
- `sweep(db, r2, env, now)` — **unchanged signature**. Replace the epoch-ms-assuming comparison with an **ISO-aware** one via a single local helper `isExpired(expiresAt, now) -> boolean` = `Number.isFinite(Date.parse(expiresAt)) && Number.isFinite(Date.parse(now)) && Date.parse(expiresAt) <= Date.parse(now)`. **PIN the contract in the module header:** `expires_at` and `now` are BOTH ISO-8601 strings (matching the whole module's documented `now`); `sweep` never assumes epoch-ms. A missing/unparseable `expires_at` on a NON-terminal, NON-revoked row is a data-integrity anomaly → counted in a new `anomalies` return field (surfaced, not silently kept), and a `// VERIFY: created_at + SWEEP_MAX_TXN_AGE hard backstop so a garbled expiry can never linger PHI indefinitely` note (backstop wired in T2's erasure pass). The terminal-status branch is unchanged (already correct).

**Invariant:** an ISO `expires_at` in the past on a non-terminal txn is now **swept** (key erased, buffer deleted, row removed); an ISO `expires_at` in the future is **retained**; the comparison never silently no-ops on a well-typed ISO clock. Return shape gains `anomalies` (unparseable-expiry non-terminal rows) without breaking the existing `{ txnsSwept, buffersDeleted, keysErased }` callers.

**Tests:** a non-terminal txn with `expires_at` 1h in the past (ISO) → swept (key erased, buffer gone, row deleted) — **this test FAILS against the current `Number()` code (proving the bug), passes after the fix**; a non-terminal txn with `expires_at` 1h in the future → retained; a terminal (`FAILED`) txn regardless of expiry → swept (unchanged); a row with a null/garbled `expires_at`, non-terminal → not erroneously swept, surfaced in `anomalies`; a second sweep over a clean table → all-zero counts (idempotent).

### Task 2 — REVOKE + `dataEraseAt`-driven erasure (`state.js#sweep` extend + schema) — **REVIEW: DUAL-ADVERSARIAL**

**Files:** Edit `functions/_connect/abdm/state.js` (`sweep` — add a consent-status pass) + `db/connect_abdm_schema.sql` (additive `data_erase_at`); Test `test/connect/abdm/sweep-erasure.test.mjs`. **Erasure-completeness is a DPDP breach surface — a residual sealed key/buffer/txn row after REVOKE or `dataEraseAt` is a violation.**

**Scope source:** spec §14 stage-6 item 1 + R15. As read, `sweep` iterates ONLY `connect_abdm_txn` on expiry-or-terminal. A consent REVOKED before its `expires_at` leaves its still-`REQUESTED`/`RECEIVING` txns (and their sealed keys + buffers) intact until expiry — a REVOKE must erase them **now**, not at expiry.

- `sweep(db, r2, env, now)` — after the existing txn pass, add a **consent-status pass**: select `connect_abdm_consent_req` rows where `status ∈ {REVOKED, EXPIRED}` OR `isExpired(data_erase_at, now)` (T1 helper, mock-safe no-WHERE enumerate-then-filter, same as the txn pass). For each, call the new internal `eraseForConsent(db, r2, env, consentRow, now)`:
  1. find that consent's txns (`WHERE consent_id=?`) → for each: `deleteBuffered(r2, txn.transaction_id)` (scoped), erase `eph_privkey_sealed` (set `""`), delete the txn row — **regardless of the txn's own status/expiry** (REVOKE overrides the FSM);
  2. on a patient-level `dataEraseAt` trigger, erase the associated `connect_abdm_carecontext` rows scoped by `(tenant_id, patient_abha_hash)` — `// VERIFY: a REVOKE of ONE consent must NOT drop a care-context registration that backs OTHER live consents; care-context erasure fires only on the patient-level dataEraseAt / a full-erase trigger, never on a single-consent REVOKE (owner to confirm the exact association semantics);`
  3. mark the consent row erased (status `EXPIRED`/a terminal marker) so a re-sweep is a no-op.
- **RETAIN the audit (R15):** `eraseForConsent` NEVER deletes `connect_audit_event` rows — the PHI-free audit is retained under DPDP §8(6). Emit a metadata-only `data.erased` audit event (`consentId`, counts) recording the erasure itself.

**Invariant (R15):** a REVOKED/EXPIRED consent, or one past `data_erase_at`, leaves **zero** derived state (no buffer object, no non-empty sealed key, no txn row) for that consent; care-context erasure is scoped and never collateral-damages another live consent; the PHI-free audit trail survives; erasure is idempotent (a second sweep = all-zero + no double-audit). Fail-closed on any storage error (`ConnectStateError`).

**Tests:** a REVOKED consent with a still-`RECEIVING` txn (buffer + sealed key present, not expired) → after sweep: buffer gone, sealed key erased, txn row deleted, a `data.erased` audit event written, the earlier `consent.revoked` audit **retained**; a consent past `data_erase_at` but status still `GRANTED` → its derived state erased; a REVOKE of consent A does NOT erase a care-context row that also backs a live consent B (`// VERIFY` association) ; a full patient-level `dataEraseAt` → the patient's `connect_abdm_carecontext` rows erased; a second sweep → all-zero counts, no duplicate `data.erased`; the audit table is never touched by erasure. **Adversarial reviewers must probe: a sealed key surviving in any code path, a buffer object left under a stale prefix, a REVOKE racing an in-flight `consumeTransfer` (decrypt-then-erase vs erase-then-decrypt residue), care-context over-erasure across consents, and whether the audit is ever wrongly deleted.**

### Task 3 — `hiNotify` reconciliation re-issue + `sealBundle` contract reconciliation (`state.js` + `hiu.js` + `fidelius.js` docstring)

**Files:** Edit `functions/_connect/abdm/state.js` (add `reconcileNotify`) + `functions/_connect/abdm/hiu.js` (`consumeTransfer`: persist `session_status` before the notify) + `db/connect_abdm_schema.sql` (additive `session_status`) + `functions/_connect/abdm/fidelius.js` (docstring only); Test `test/connect/abdm/reconcile-notify.test.mjs`.

**Carry-forward sources:** [Stage-4 T7 adversary B] `hiNotify` at-most-once — and [Stage-4 T7 adversary A] the `sealBundle` docstring/contract.

**Sub-item A — `hiNotify` reconciliation (adversary B).** As read, `consumeTransfer` (hiu.js:286-291) does `won = claimAck(...)` then `gateway.post("hiNotify", …)` then `deleteBuffered` then `advanceStatus`. A transient gateway throw AFTER the winning CAS strands the txn: `ack_claimed=1`, status still `RECEIVING`, buffer intact — and a retry loses the CAS → **the receipt is never re-sent, the txn never terminalizes** (until Task-2 expiry). Fix (root cause): make the finalization **recoverable**.
- **Schema (additive):** `connect_abdm_txn += session_status TEXT` — the computed outcome (`TRANSFERRED|PARTIAL|FAILED`).
- **`consumeTransfer` (surgical):** immediately AFTER `won = claimAck(...)` and BEFORE the `hiNotify`, persist `UPDATE connect_abdm_txn SET session_status=?,updated_at=? WHERE transaction_id=?` — so the outcome is durable the instant the ack is claimed. (Ordering: claim → persist outcome → notify → delete → advance; a crash/throw anywhere after the claim is now recoverable from `session_status`.)
- `reconcileNotify(db, r2, env, deps, now) -> { reissued, terminalized }` where `deps = { gateway }` — enumerate txns with `ack_claimed=1 AND status='RECEIVING' AND session_status IS NOT NULL` (mock-safe filter-in-JS), and for each **idempotently** re-run the tail: `gateway.post("hiNotify", { transactionId, sessionStatus: row.session_status })` → `deleteBuffered(r2, transactionId)` → `advanceStatus(db, request_id, "RECEIVING", session_status, now)`. A re-run after success finds status terminal → skipped (idempotent). Fail-closed per row; a gateway error on one row does not abort the others (best-effort, audited).

**Sub-item B — `sealBundle` contract reconciliation (adversary A), DOCSTRING ONLY.** As read, `fidelius.js#sealBundle` (:62-69) says "the ABDM HIP-encrypt stage (Stage 5) is responsible for **one keyMaterial per entry**"; but the as-built `consumeTransfer` (hiu.js:263-274) derives ONE `secret`/`ourNonce`/`hipNonce` and loops `openEntry` across a page's `entries[]` — i.e. the live consume side is **one keyMaterial per transfer PAGE**. Reconcile the docstring so encrypt + consume agree: the live protocol is **one keyMaterial per transfer page, and a well-behaved page carries exactly one entry** (so per-page = per-entry); the consume side tolerates a hostile multi-entry-under-one-keyMaterial page only because it checksum-verifies each entry post-decrypt. Mark the live-protocol shape `// VERIFY: confirm against the ABDM /health-information/transfer wire-shape (one keyMaterial per page, one entry per page)`. No code change — a comment in `consumeTransfer` cross-references it.

**Invariant:** a claimed-but-non-terminal txn (lost receipt) is **recovered** on the next reconcile pass, idempotently (re-notify + delete + terminalize; a terminal txn is untouched); the `sealBundle`/`openEntry`/`consumeTransfer` contract is internally consistent and matches the documented (VERIFY-pinned) wire shape.

**Tests:** simulate a lost receipt — a txn with `ack_claimed=1`, `status='RECEIVING'`, `session_status='TRANSFERRED'`, buffer present (gateway threw on the first notify) → `reconcileNotify` re-issues one `hiNotify`, deletes the buffer, advances to `TRANSFERRED`; a second `reconcileNotify` → no-op (terminal, skipped); a txn still legitimately `RECEIVING` with `ack_claimed=0` → NOT reconciled (never claimed); a reconcile where one row's gateway throws → the other rows still reconcile; `consumeTransfer` now writes `session_status` before the notify (assert persisted even if the injected gateway throws). (Docstring reconciliation is verified by reading — no runtime test, but the multi-entry tolerance is already covered by the Stage-4 per-entry-decrypt tests.)

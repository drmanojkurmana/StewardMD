# OPD A-to-Z plan (2026-09-24)

Owner ask: fix everything from the OPD + StewardID/Ni-Key audit, make it premium. Built in this order,
one commit per item, full suite green before each push. Resume from the first unchecked item.

Decision taken without asking (reversible): patient IDs use prefix `SMP-` + a check character, so a
patient ID can never be read as a clinic code (`SMD-`).

## Phase 1 - identity (a wrong-patient event is the one bug a hospital never forgives)
- [x] 1. StewardID minted and stored by the SERVER, reserved globally with a create-only write in the
       same commit as the patient (duplicates impossible across devices and clinics). Format
       `SMP-XXXX-XXXXC`, Crockford Base32, Luhn mod-32 check char (catches typos and swaps).
       Client stops minting; it shows what the server returns.
- [x] 2. Server resolve (`GET /identity/resolve`) and revocation (`POST /identity/revoke`) so a lost
       Ni-Key card stops working on every device, not one.
- [ ] 3. Client cache holds no PHI: id -> display hint only, expiry, wiped on sign-out.
- [x] 3b. (owner, 2026-09-24) The patient QR does not scan: generate it with the SAME mechanism the
       prescription QR uses, and make one easy find-patient flow for QR, Ni-Key, manual entry and
       barcode - all four land on the same server resolve.

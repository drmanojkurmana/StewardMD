## 1. Repo reality that shapes every decision

These facts (verified during inspection) constrain how the redesign must be implemented:

- **Buildless static PWA + Capacitor.** Source of truth = root `*.js` / `*.html` / `*.css` loaded directly by `index.html` (no bundler, no transpile, **no TypeScript**). `scripts/build-www.sh` only *copies* files into `www/` (the Capacitor `webDir`). `www/`, `ios/App/App/public`, `android/app/src/main/assets/public` are **generated — never hand-edit**.
- **No lint, no typecheck, no `npm test`.** Verification = the ~70 headless-Chrome runners in `test/*.mjs` (each self-spawns `test/serve.mjs` from repo root + Chrome via CDP) plus `npm run build:www`. The Phase-gate "run lint/typecheck" becomes **"run the relevant `test/run-*.mjs` safety runners + web build."**
- **No router.** Screens are DOM overlays toggled by class (`.on`/`.hidden`/`.open`) and layered by a z-index token scale (`--z-fab…--z-intro`, `index.html:26`). Back is universal via `swipe-back.js` (iOS swipe + Android hardware back → click top-most `*-back/*-close` control by z-index, else clinical-engine `_SMD_goBack`, else exit). **A redesign must not assume route-based nav or add `pushState`.**
- **Module registry = window globals.** `DX, ELYTE, MEDCALC, INF, MEDDB, MEDDRUGS, ABG, ASP, ICU, SB, GHIS, MEDLIST, INTERACTIONS, SMD_AI, SMD_VOICE, SMD_WATCH, SMD_WS, CASESHARE, SMD_ACCOUNT, ICU_STATE …` Each exposes `.open()/.close()`; `goHome()` and `swipe-back` depend on those APIs and on hard-coded id lists (`home.js:231–240`). Renaming ids/classes/globals breaks nav **silently** (no compile error) and breaks the headless test suite (which polls for these globals).
- **`app.js` is minified (650 KB)** and owns the classic clinical engine (`#inputCard`/`#outputArea`/`#runBtn`/`_SMD_goBack`), the `SB` sidebar, base theme tokens, and Firebase/`SMD_CASES`. It is augmented via public seams, **never edited directly**.
- **Theme tokens are centralized-but-duplicated.** Base palette `:root` at `index.html:26` (`--teal/--ink/--paper/--panel/--line/--slate` + `--green/--yellow/--orange/--red` status ramps) is the shared contract (`reasoning.js` uses `var(--teal)` ×85). But parallel copies exist in `ui-v3.css` (`--v3-*`), `home.js` (`--h*`), `icu.js` (`--primary/--ok/--warn/--danger`), `image-engine.js` (`--ie-*`), and small `--bg` islands (`electrolytes/antibiogram/caseshare`). Three dark triggers coexist: `body.dark`, `body.v3-dark`, `:root[data-theme=dark]`, plus `@media(prefers-color-scheme)` in `image-engine.js`. **7 accent themes** (`html[data-theme]`) + **7 fonts** + density/zoom are an accessibility axis (`home.js` `smd_display_v1`).
- **Cache-busting is manual:** `?v=goldNNN` on each `<script>` in `index.html` + `CACHE` in `sw.js` (currently `stewardmd-gold298`) must be bumped together on every change, or the service worker serves stale JS.
- **Cannot render/screenshot UI in this environment** (documented constraint). "Before/after" visual evidence in Phase 5 will rely on the design-package reference screenshots + manual device capture by the user.

## 3. Implementation order (mapped to the requested phases)

- **Phase 1 — Design foundation** → board **1b** (+ **3e** patterns). Canonical tokens (light/dark/severity), typography, spacing/radius/elevation, reusable primitives, skeleton/empty/error/offline/success states, safe-area + keyboard-safe helpers, a11y (labels/contrast/44px/focus). **No clinical workflow changes.**
- **Phase 2 — Navigation & dashboard** → **1f** (5-tab shell + More sheet, retire drawer), then **1c/1d → superseded by 3a** (home rebuilt with full parity), Watch-Lab alert / resume-case / quick actions / tools grid. Real data + existing routes only; preserve deep-links + iOS/Android back.
- **Phase 3 — Core clinical workspace** → **1e** (ICU Overview restyle), **2a** (Dx flow), **2b** (decision result), **2c** (Drugs), **2d** (Interactions), **2e** (MaiK), **2f** (Scan/OCR/Vision), **2g** (Cases). AI stays labelled + editable-before-confirmed.
- **Phase 4 — Secondary screens** → **3b** (onboarding/permissions gate), **3c** (settings), **3d** (account/subscription), **3a** parity finalization, **3e** states everywhere, **3f** parity ledger reconcile; search + confirmations/destructive safety.
- **Phase 5 — Validation & polish** → complete `TEST_CHECKLIST.md`, produce `docs/redesign/IMPLEMENTATION_RESULTS.md` (boards done, test results, iOS/Android manual checks, web/Cloudflare build, limitations, deferred work, before/after where feasible).

1. `index.html` (`:root` inline `<style>` at line 26) — add canonical + **severity** tokens (light) and extend `body.dark` (via anchored replacement; the block is a single minified line — edit carefully).
2. `ui-v3.css` (`:root --v3-*` 8–44) — align `--v3-*` to alias the canonical tokens (keep `--v3-primary → var(--teal)`).
3. `home.js` (`--h*` injected layer 478–509) — alias `--h*` to the canonical tokens instead of re-declaring hex.
4. **New** `redesign-system.css` (added to `build-www.sh` copy set + `index.html` with `?v=gold…`) — the shared component primitives (buttons/cards/chips/badges/inputs/banners/skeletons/state patterns) + Material Symbols wiring, scoped so it does not disturb `app.js`-owned classic markup.
5. Bump every touched `?v=goldNNN` + `sw.js` `CACHE`.

*(icu.js `--primary/--ok/--warn/--danger` and image-engine `--ie-*` are mapped onto the canonical severity/accent tokens in their respective phases — not force-unified in Phase 1, to avoid destabilizing 63+ consumers at once.)*

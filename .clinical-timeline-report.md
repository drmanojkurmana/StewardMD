## Output shape
`{ events: [Event], undated: [Event-without-date], counts }`

`Event = { date, kind, title, detail?, code?, system?, value?, unit?, abnormal?, flag?, resourceType, evidence }`
- `evidence = { resourceType, id, sourceField }` — traces every event back to its exact source resource + which date field was read.
- Observation events also carry `value`/`unit`, and `abnormal:true`+`flag` when abnormal.
- `undated[]` items are the same shape with **no `date` key**.

### Event kinds (from SCCM resources with a real date)
- `encounter` — Encounter period.start/date; title = reason, else class/status
- `condition-onset` — Condition onset; title = condition text/code
- `lab-result` / `observation` — Observation effectiveDateTime (laboratory category => `lab-result`, else `observation`); title = code text + value + unit; abnormal marked via interpretation flag AND/OR out-of-range value
- `procedure` — Procedure performedDateTime/date (SCCM v1 has none; defensive passthrough, `[]` when absent)
- `diagnostic-report` — DiagnosticReport effectiveDateTime/issued; title = code/type, detail = conclusion
- `medication` — MedicationStatement effectivePeriod.start; title = drug + dose; **no med date => undated (never invented)**

### counts
Per-kind tally over dated events + `undated` count + `total` (events+undated). Empty/malformed bundle => `{}`.

## Safety boundary (all verified by tests)
- **No fabrication of dates:** date carried VERBATIM from the source (`dateStr`, never reformatted). A resource with no parseable date goes to `undated[]` and is **never** assigned a date. Test asserts `"date" in item === false` for undated items and that every emitted date string appears in the source JSON.
- **No fabrication of content:** no-fabrication test asserts every alpha token of every title/detail + every code/system/value/unit is present verbatim in the source bundle. Titles are pure concatenations of verbatim record values (space-separated); structural type-label fallback only when the record carries no text/code.
- **Undated handling:** never dropped, never dated. Both a Condition with no onset and a MedicationStatement with no effectivePeriod land in `undated[]` with their kind + verbatim title intact.
- **Deterministic:** sort is date DESC -> kind ASC -> title ASC, stable insertion-order tie-break; no `Date.now`, no `Math.random`. Repeated calls are byte-identical. Partial dates (YYYY, YYYY-MM) parse+sort correctly (UTC via `Date.parse`) yet are carried verbatim.
- **Bounded:** each raw resource list is sliced to `opts.maxEvents` (default 500, hard ceiling 10000) BEFORE sorting; final events/undated also capped. 10,000-observation hostile bundle => 500 events, no hang.
- **Never throws:** empty/null/array/primitive/`conditions:"not-an-array"`/`observations:[null,1,"x"]` all return `{events:[],undated:[],counts:{}}`.
- No clinical judgement, no decisions, no LLM — structures the record only.

## Concerns / notes
- Bounding slices raw lists BEFORE sorting per the spec, so on a HOSTILE bundle larger than `maxEvents` per type the "most recent first" guarantee can drop items beyond the cap (documented tradeoff; normal bundles under the cap are exact).
- `abnormal`/`flag` are emitted as optional top-level fields on observation events (only when abnormal) so the UI can highlight — a documented extension of the base shape, consistent with the assembler's `flag`.
- kb/dist / no-em-dash: generated titles/details use ASCII separators only (asserted no em/en-dash).

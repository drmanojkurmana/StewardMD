## Security-review fix (2nd pass)
1. **CRITICAL — redirect-follow SSRF closed.** New `functions/_connect/onboard/net.js` `makeSafeFetch`: does
   `redirect:"manual"`, RE-VALIDATES every hop's `Location` with `assertPublicHttpsUrl` (blocked -> error
   class `ssrf`, nothing sent onward), and on a CROSS-ORIGIN hop DROPS all request headers + the body so the
   bearer / signed SMART client-assertion never reaches a redirected host. ALL onboard outbound fetches now
   route through it: probe discovery (`.well-known` + `/metadata`), the signed token POST, the `/metadata`
   and `/Patient?_count=1` probes (`probe.js`), and the connector's reads/searches via `ctx.fetch` (`pull.js`).
   Defense-in-depth: the reused `fhir-r4/connector.js` readPatient + validate now use `redirect:"manual"`
   (like paginate) so the engine path never auto-follows a 3xx on an authenticated request either.
2. **Trailing-dot host bypass closed** (`ssrf.js`): host is stripped of a trailing `.` before the name checks,
   so `localhost.` / `metadata.google.internal.` / `*.local.` are rejected.
3. Adversarial tests added (`redirect-ssrf.test.mjs` + `ssrf.test.mjs`): metadata-IP / private-IP / http
   redirect blocked and never fetched; cross-origin redirect drops bearer + custom header + assertion body;
   same-origin redirect preserved (functional); runProbe + pullConnection redirect-to-metadata-IP blocked;
   trailing-dot names + alt-encoded loopback hosts (`2130706433`, `0x7f.0.0.1`) rejected.
4. DNS-rebinding stays the documented `// VERIFY` residual (resolve-then-pin later). **Redirect-follow (item 1)
   was the live-exploitable hole and it is now closed.**

## Key security decisions
- **SSRF guard** (`onboard/ssrf.js` `assertPublicHttpsUrl`) called at save AND before every fetch (base, discovered
  token endpoint). DELIBERATELY replaces the Phase-0 sandbox host-allowlist: requires https, rejects userinfo,
  rejects IPv4 private/loopback/link-local/CGNAT (10/8, 172.16/12, 192.168/16, 127/8, 0/8, 100.64/10, 169.254/16
  incl. 169.254.169.254), IPv6 ::1/::/fc00::7/fe80::10 + IPv4-mapped (dotted AND Node's hex `::ffff:a9fe:a9fe`),
  and localhost/*.local/*.internal/*.localhost. Unit-tested per case. Public IP literals are allowed (per task).
- Credentials **envelope-sealed** (reused `secrets.js`) inline in the config JSON; never returned by list/test;
  delete erases them with the row.
- Tenant/actor **server-derived** (reused `identify` + `enterprise/guard.requireCan`); fail-closed RBAC.
  save/delete=connector:write, test=connector:validate, list=connector:read; **pull=connector:read AND denies
  auditor** (PHI). Errors sanitized to `{ error: <class> }` only — no stack/URL/token ever leaks.
- Reuse (not forked): `signClientAssertion` (SMART crypto), the `fhir-r4` connector (`fetchPatient`+`normalize`,
  run in no-SMART bearer mode so both token and SMART pulls work on any public host), `normalizeFhir`,
  `validateBundle`, `audit.js`, `identify`/`ownerOK`. NOT reused: `discoverSmart`/`acquireAccessToken`/
  `assertSandboxAllowed` — those are frozen to sandbox hosts by design; the onboard layer does its own
  SSRF-guarded discovery/token instead.

## `// VERIFY` / residuals for the owner
- **DNS-rebinding** is a documented residual: a hostname that passes the literal-IP + name checks but RESOLVES
  to a private IP at fetch time is not caught. Close later with resolve-then-pin (noted in `ssrf.js`).
- **Public-exfil host**: the guard blocks PRIVATE ranges only, so a discovered token endpoint on an attacker's
  PUBLIC host is not host-rejected — BUT the signed assertion's `aud` is bound to that exact endpoint (no replay
  elsewhere), and any cross-origin REDIRECT now drops creds/body (see fix item 1). Acceptable for Increment 1.
- **Custom-header token pull**: the probe honors a custom `headerName`, but the reused connector emits only
  `Authorization: Bearer`, so pull for a custom-header connection uses Bearer (noted in `pull.js`).
- **PHI gate for pull**: task says owner/admin-gated; RBAC nominally reserves PHI (context:load) for clinicians.
  I gated pull at connector:read + auditor-deny so owner/admin/clinician may pull-for-viewing during onboarding.
  Owner should ratify whether onboard-pull should be clinician-only.
- Storage: NO schema ALTER needed — reuses `connect_connector_config` (connector_id=connectionId, config JSON
  holds name/authMethod/sealed/lastTest); documented in `db/connect_schema.sql`.
- SMART Backend Services needs client key material (privateKeyJwk/kid/alg). The task's abbreviated body lists
  only `clientId`; I accept the key material under `auth.*` (sealed) so SMART can actually complete. `method:"token"`
  is the fully-featured self-service path.

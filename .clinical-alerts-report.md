# Clinical Alert Framework — Part 4 (MaiK Orchestration)

**Status:** DONE. Buildless, no new deps, no LLM, no network, pure/deterministic, TDD, zero regression.

## Files
- `functions/_connect/maik/clinical-alerts.js` — new pure module (consumes the Clinical Context Assembler output).
- `test/connect/maik-clinical-alerts.test.mjs` — 14 tests (written first, red → green).

## API / output shape
`deriveClinicalAlerts(clinicalContext, opts = {}) -> { alerts, counts }`
- `alerts[]`: `{ kind, severity, message, evidence, refs }`
- `severity`: `critical | warning | info` (fixed vocab; sorts critical-first)
- `counts`: per-kind tally, only present kinds (empty context → `{}`)
- `opts`: `maxPerKind` (default 50), `polypharmacyThreshold` (default 5)

## v1 alert kinds
- **allergy-conflict** — current med matches an allergy on name OR code (exact/clear-substring, case-insensitive). High criticality → `critical`, else `warning`. evidence `{med, allergy}`.
- **duplicate-therapy** — ≥2 current meds sharing a normalized name or a code (union-find grouped) → `warning`. evidence `{drugs:[...]}`.
- **abnormal-lab** — one flag per abnormal lab; `critical` when the flag is a panic marker (HH/LL/…) or (if range present) the value is >1 full range-width out, else `warning`. evidence = the lab.
- **polypharmacy** — current-med count ≥ threshold → `info`. evidence `{count}`.

## Behavior
Missing/empty/hostile context → `{alerts:[], counts:{}}`, never throws (try/catch + array guards). Bounded (per-kind cap). STABLE deterministic ordering: severity desc → kind → evidence signature. No wall clock, no randomness.

## Safety guards (verified by tests)
- **Surface-not-decide / no-recommendation:** every message is framed "possible … please review"; a test asserts no message contains any directive/dosing verb (stop/start/increase/decrease/prescribe/discontinue/hold/administer/reduce/raise/initiate/titrate/switch/give) nor decisive language (diagnos*/must/contraindicated).
- **No-fabrication:** every clinical string in an alert (evidence names/codes/values + refs) appears verbatim in the source context; evidence carries the source objects by reference, invents nothing.

## Honest limitations (documented in the module header)
- Matching is CONSERVATIVE and NOT exhaustive: no drug DB in v1, so a brand/generic or cross-reactive-class name mismatch (e.g. "amoxicillin" vs a "penicillin" allergy) is a KNOWN false-negative. It is a decision aid, not a guarantee of completeness.
- Real drug-interaction and renal-dose alerts need the main app's engines — a later integration, out of scope for v1.
- `abnormal-lab` severity relies on the flag because the assembler drops reference ranges; the range-distance path fires only if a caller enriches labs with `low`/`high`.

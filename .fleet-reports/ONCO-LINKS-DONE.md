## What was built

1. Mapping table generated by code: tools/build-cancer-protocol-map.mjs from oncotree
   navigator protocolRefs + protocol diseaseId fallback + reviewed overrides in
   kb/cancer-mapping-overrides.json. Outputs kb/cancer-mapping.json and the
   buildless client cancer-protocols-map.js (window.SMD_ONCO_KB_MAP).
2. KB reader Protocols section (reasoning.js): grouped by setting/line with regimen
   one-liner; tap opens the Oncology viewer when available (feature flag guarded,
   try/catch), otherwise a read-only card, never a dead link. Reverse link on the
   protocol sheet: "Read the KB article: X" (protocol-sheet.js).
3. MCQ Know more Protocols row (prep-reason.js kmTargets/knowMoreHtml/sheet, "See
   protocols (N)" after the KB/lesson links). Builder (tools/prep-links.mjs build +
   stampLinks) carries protocol ids with via "cp", small [id, score, "cp"] triples.
   Gate: oncoEvKbId() - specific-tier evidence (srcPack/exact) always counts;
   topic-tier counts only for the module's own mapped topic or a cancer named in
   stem/keyed answer. Distractor-only or explanation-only mentions never attach
   regimens (owner: no wrong links). LINKS_VER stays v2; no new /api/prep/bank paths.
4. Tests: test/cancer-protocols-map.test.mjs, test/prep-links-onco.test.mjs (12 tests:
   mapping, cervical 7/4, gate cases incl. the real CIDP/amyloid distractor case),
   tools/audit-onco-mcq-links.mjs (100-sample audit, ONCO_LINKS_DIR overridable),
   test/run-onco-links-ui.mjs (browser: cervical article + MCQ row + 390px/44px/themes).

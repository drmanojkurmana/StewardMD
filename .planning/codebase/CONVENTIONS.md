# Coding & Clinical Conventions

**Analysis Date:** 2026-09-11

## Architecture & Code Conventions

**Buildless Philosophy:**
- Core application code at the root is pure vanilla JavaScript (ES modules and clean browser globals) without intermediate transpilation steps.
- CSS is organized modularly by domain (`surgx.css`, `thorex.css`, `ward.css`, `sknx-screens.css`).
- Cache-busting is managed explicitly via version tokens (`?v=...`) in `index.html`.

**State Management:**
- Each clinical domain maintains a dedicated store module (`surgx-store.js`, `thorex-store.js`, `sknx-store.js`).
- Stores manage in-memory caching and serialize persistent state to SQLite / SecureStorage.

**Security & Clinical Safety Invariants:**
- **Zero Raw PHI in Transit/External Clouds:** Patient health information must never be sent unencrypted to third-party endpoints or cloud backups.
- **Client-Side Key Derivation:** Cryptographic routines in `surgx-backup.js` and `vault/` require explicit user passphrases with PBKDF2 key stretching and fresh random salts.
- **Fail-Closed Clinical Gates:** When clinical inputs are missing or uncertain, the algorithms must refuse to generate an automated recommendation rather than inventing or hallucinating clinical protocols.
- **Auditability:** All automated suggestions link directly to indexed medical evidence citations and clinical guideline references.

## Error Handling & Logging

- Standard `try...catch` blocks wrapping asynchronous native plugin calls and database queries.
- User-facing error notifications through non-intrusive toast messages (`toast.js`) rather than generic browser alerts.
- Diagnostic assertions in development that flag mismatched schema versions or missing deep-link targets.

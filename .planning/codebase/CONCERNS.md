## Architecture & Codebase Concerns

1. **Large Monolithic Controller Files:**
   - Files like `ward.js` (~365 KB), `surgx-screens.js` (~119 KB), and `thorex-screens.js` (~98 KB) contain high complexity and mixed responsibilities (UI rendering, business logic, and API calls).
   - Recommendation: Progressively decompose into smaller focused sub-modules per view/screen.

2. **Untyped JavaScript at Scale:**
   - The entire codebase is written in pure JavaScript without TypeScript type definitions. While this preserves the buildless PWA architecture, refactorings carry higher risk of runtime regressions if test coverage has gaps.
   - Recommendation: Add JSDoc type annotations (`@type`, `@typedef`) to core data schemas (patient models, note schemas, EMR mappings) for IDE autocompletion and `tsc --noEmit` validation without introducing a build pipeline.

3. **On-Device ML Memory & Device Compatibility:**
   - Multiple local native plugins (`capacitor-llama`, `capacitor-whisper`, `capacitor-sknx-vision`) run neural network inference on-device.
   - Risk: Memory exhaustion or thermal throttling on older devices (iOS devices with < 4GB RAM or Android devices with fragmented NPU support).
   - Recommendation: Maintain robust fallback paths to cloud vision/LLM APIs when native hardware acceleration is insufficient.

4. **Multi-Platform Native Plugin Synchronization:**
   - Custom native Capacitor plugins in `local-plugins/` require manual `npx cap sync` and dual maintenance in Swift (iOS) and Kotlin/Java (Android).
   - Recommendation: Establish automated CI verification for both iOS and Android native builds on every pull request.

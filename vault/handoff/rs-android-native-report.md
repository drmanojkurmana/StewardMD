# rs-android-native report — Android background audio + secure Spotify token storage (2026-10-31)

Branch `prep-reels-sound-2`. **Native changes need a store build to reach phones — an OTA/web update cannot deliver this plugin.** No Spotify approval request was sent or drafted. No paid calls; no network in tests.

## What was built

- **New local plugin `@stewardmd/capacitor-prep-sound`** ([local-plugins/capacitor-prep-sound](../../local-plugins/capacitor-prep-sound/README.md)), Android only, exposed as `Capacitor.Plugins.PrepSound`, following the `capacitor-capture-guard` pattern (`file:` dep, `android/` module, explicit `registerPlugin` in `MainActivity`).
  - [PrepSoundService.java](../../local-plugins/capacitor-prep-sound/android/src/main/java/in/stewardmd/prepsound/PrepSoundService.java): foreground media-playback service using **platform `MediaPlayer` + `android.media.session.MediaSession` only** (the repo has no Media3 dependency and none was added; only the already-used AppCompat is on the compile path, for the activity type). Looping playback of the four first-party tracks, foreground notification with Play/Pause + Stop and lock-screen controls via the MediaSession, audio focus (pause on loss/transient loss, duck to 20% on `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK`, restore on gain; a transient-focus pause resumes, an explicit web-layer pause/stop never does), pause on `ACTION_AUDIO_BECOMING_NOISY`, stop on plugin `stop()` (the call PrepReels video / TTS / mock-test hush routes through `PREP_SOUND_WEB.stop()`). No autoplay: the service is inert until the plugin forwards an explicit user tap. Plugin manifest declares `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` and `foregroundServiceType="mediaPlayback"` (targetSdk 36); no existing permission or service was changed, and `POST_NOTIFICATIONS` is not re-declared.
  - [SecureStore.java](../../local-plugins/capacitor-prep-sound/android/src/main/java/in/stewardmd/prepsound/SecureStore.java): `setSecret`/`getSecret`/`removeSecret` backed by an AES-256-GCM key generated in the Android Keystore (12-byte random IV per write, ciphertext in private SharedPreferences). **No `EncryptedSharedPreferences` dependency.** Keys are shape-validated, values capped, and neither values nor ciphertext are ever logged.
  - [PrepSoundPlugin.java](../../local-plugins/capacitor-prep-sound/android/src/main/java/in/stewardmd/prepsound/PrepSoundPlugin.java): `play/pause/stop/setVolume/getStatus/isAvailable` + the three secret methods; service state is re-emitted to JS as `playbackStateChange`.
  - **WAV assets:** [tools/prep-sound-render-wavs.mjs](../../tools/prep-sound-render-wavs.mjs) deterministically renders the four web synth recipes (`rain_soft`, `night_quiet`, `deep_drone`, `ocean_slow`; seeded PRNG, original generated noise/pads only) to 5 s, 22.05 kHz mono WAVs in the plugin's `android/src/main/assets/prep-sound/` (~215 KB each). `--check` verifies the committed files byte-for-byte.
- **[prep-sound-native.js](../../prep-sound-native.js)** (`window.PREP_SOUND_NATIVE`): the adapter selected on Capacitor native Android with the plugin present. It mirrors the `PREP_SOUND_WEB` synchronous surface (`start/pause/stop/setVolume/isPlaying/current/supported/bindMediaKeys`) plus `refreshStatus` and the secret passthrough. iOS reports unsupported (`selectBackend` → `web`), so the web path is used there, unchanged.
- **Core/web wiring (owned files only):** [prep-sound-core.js](../../prep-sound-core.js) gains `TRACK_FILES` and the pure `selectPlaybackBackend(env)`; [prep-sound-web.js](../../prep-sound-web.js) delegates start/pause/stop/volume/Media-Session binding to `PREP_SOUND_NATIVE` when it reports available, passing the user's stored `backgroundPlayback` preference, and falls back to WebAudio otherwise. [prep-sound.js](../../prep-sound.js), its CSS and the loader were **not** touched.
- **Spotify secure storage:** [prep-sound-spotify.js](../../prep-sound-spotify.js) persists **only the refresh token** under `prep_sound_spotify_refresh_token`, only on native Android with the plugin present (web/iOS stay memory-only). Exchange and every refresh rotation re-persist it; `disconnect()` clears it; on cold start `restoreSession()` seeds the refresh token and exchanges it for a live session (a dead token clears the persisted copy). Access tokens are never persisted and tokens are never logged.

- `node tools/prep-sound-render-wavs.mjs --check` — all four WAVs byte-identical to the renderer.
- `node --check` on every touched/new JS file — OK.
- **Gradle compile was NOT run successfully in this sandbox:** `./gradlew :stewardmd-capacitor-prep-sound:compileDebugJavaWithJavac` (with the specified `JAVA_HOME`/`ANDROID_HOME`) fails before configuration because the sandbox denies the Gradle wrapper lock file under `~/.gradle` and, with a `/tmp` `GRADLE_USER_HOME`, denies the daemon socket (`SocketException: Operation not permitted`); unsandboxed execution needs human approval, which is disabled. The Java was written against the same Capacitor/AppCompat APIs as `capacitor-capture-guard` and reviewed line by line, but **the lead must compile it**; treat the module as unverified until then.

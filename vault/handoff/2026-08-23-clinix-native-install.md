## What this install is for

Two separate things happen in one rebuild, and it is worth keeping them apart:

1. **CliniX reaches the device.** It is pure `www/` (9 root JS/CSS files + a 236 KB `clinix/` JSON
   directory). No native code at all.
2. **OTA gets armed.** `@capgo/capacitor-updater` is in `package.json` but has NEVER been synced
   into the native project. This rebuild is what puts the plugin on the device. **OTA does not
   deliver this install; it delivers the next one.**

## The two steps that are easy to skip and silently break it

```bash
npm install     # @capgo/capacitor-updater is NOT in node_modules on a fresh clone
npx cap sync    # regenerates android/capacitor.settings.gradle WITH the updater plugin
```

Evidence it has not happened yet: `android/capacitor.settings.gradle` lists ~20 plugins and
**`capacitor-updater` is not among them**. That file is generated by `cap sync`.

Skip either and the build still succeeds, CliniX still works, and `native-ota.js`
`available()` (`:109`, `isNative() && !!plugin()`) stays **false** forever. The rebuild that was
supposed to arm OTA will not have.

## Sequence

```bash
git fetch origin && git checkout claude/stewardmd-new-module-5uf324 && git pull
npm install
bash scripts/build-www.sh
bash scripts/verify-clinix-bundle.sh          # must print PASS
npx cap sync
bash scripts/verify-clinix-bundle.sh          # last line should now say OTA plugin ok
```

`scripts/verify-clinix-bundle.sh` exists because of one silent failure: root `*.js`/`*.css` reach
`www/` by glob, but `clinix/` is a DATA directory needing an explicit `cp -R` in
`build-www.sh` (added, line ~97). Without it the app installs cleanly, the tile appears, and every
pathway renders **empty on the device** — the same bug `build-www.sh` already documents against
itself for the onco catalogs. Never install a bundle where that script does not print PASS.

## iOS specifics — NOT VERIFIED (no Mac in the authoring container)

- iOS uses **SPM, not CocoaPods**: `ios/App/CapApp-SPM`, plus the `experimental.ios.spm` block in
  `capacitor.config.json`. There is **no `ios/App/Podfile`**. Let Xcode resolve packages after sync;
  do not go looking for `pod install`.
- CLAUDE.md's build gotcha applies exactly here:
  ```bash
  find ios/DerivedData -name App.app                       # flat OR ECID-subfolder, never assume
  grep -c clinix "<that path>/public/index.html"           # expect >= 8, BEFORE installing
  xcrun devicectl device uninstall app --device <id> in.stewardmd.app
  ```
- **The uninstall matters more than usual.** `sw.js` `CACHE` was bumped to
  `stewardmd-nb-consult1-onco6-atlas1-maikllm1-wr1-clinix1`; a surviving old service worker would
  serve a bundle with no CliniX in it and look like the build failed.

## Seeing it once installed — NOT VERIFIED on a real device

The flag is **OFF** and there is no URL bar on native, so:

1. **Settings → Experimental → "CliniX · Clinical learning (Beta)"** → reload. Tile appears on the
   home grid (`home.js` `HOME_TOOLS`, act `clinix`, icon `school`).
2. CliniX → Respiratory → COPD gives **"Awaiting clinical review"**. That is the review gate working,
   not a failure: all content is `review.status: ai_drafted`. Tap **"Turn on author mode"**
   (sets `smd_clinix_draft`) and the full 14-chapter pathway loads.
3. Worth exercising: the **percussion lesson** (tap the numbered zones), a **case** (ask "do you
   smoke", then guess the diagnosis early to get the "right answer, thin workup" verdict), and an
   **OSCE** ticking everything except consent.

## Known-inert on this build

**The MaiK tutor will not answer.** Its server half (`TUTOR_SYS` + the `clinix` quota remap in
`functions/api/ai/[[path]].js`, and `mode` in `reasoning.js`) only goes live when that reaches
`main` and Cloudflare Pages deploys. With `smd_clinix_tutor` on, "Ask MaiK" renders and fails to
its honest error state. This is expected, not a regression.

## What to report back

Only a real device can answer these, and the authoring session could not:

- Do type sizes and tap targets hold at real DPI? Everything was designed and screenshotted at an
  emulated 393px.
- Does the interactive percussion SVG respond to a real finger? The delegated listener handles SVG
  targets (proven in Chrome via a dispatched event), but a genuine touch on an `<svg><g>` on iOS
  WKWebView is untested.
- Does haptic feedback fire? `SMD_HAPTICS` is iOS-native only by design.
- After `cap sync`, does `window.Capacitor.Plugins.CapacitorUpdater` exist and does
  `SMD_OTA.available()` return **true**? That is the single check that says OTA is armed.

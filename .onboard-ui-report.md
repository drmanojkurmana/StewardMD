## What it does
- Owner/admin auth exactly like `admin/index.html`: same Firebase config, same `tok()`/`api()` bearer-token helper (`Authorization: Bearer <idToken>`), same sign-in-with-Google + `onAuthStateChanged` flow, gate card when signed out. Server enforces the real `requireCan` RBAC; the page just carries the token.
- **Organization / tenant ID** field at the top. The shipped router derives the actor server-side but takes the *tenant* from `body.tenantId` (POST) or `?tenant=` (GET/DELETE), and `resolveTenant` requires the caller be a member. So the UI collects the tenant ID and sends it on every call. (If the backend later auto-selects a sole tenant, this field can default/hide.)
- **Add connection** form → `POST /onboard/emr`: name; type picker (FHIR active, HL7 v2 / CSV / REST / DICOM shown disabled "coming soon" so the multi-type direction is visible); FHIR base URL; auth method Token/API-key (token + optional custom header name) or SMART (clientId + optional tokenEndpoint + the key material the backend seals under `auth.*`: privateKeyJwk/kid/alg). Token input is `type=password` and the form is cleared on save. Two buttons: "Save connection" and "Save and test connection" (the in-form test = save then `test/:id`).
- **Test** (per row and the in-form "Save and test") → `POST /onboard/test/:id`: shows "Connected. FHIR <version>, <software>." on success, or a specific message per error class (bad-url / tls / unauthorized / not-fhir / unreachable). Refreshes the list so the row's last-test badge updates.
- **Connections list** → `GET /onboard/list?tenant=`: renders name, type badge, base **host** only, and last-test status badge (Connected / <error> / not tested). Never shows secrets (backend omits them; list projection has no token/sealed material).
- **Pull a patient** (per row, expandable) → `POST /onboard/pull/:id` with `{patientId}`: renders the normalized SCCM bundle as pretty JSON for v1 viewing.
- **Delete** (per row, confirm first) → `DELETE /onboard/:id?tenant=`.
- **Flag-off**: a 404 from `GET /list` (the route only exists when the flag is on) flips to a graceful "EMR Connect is not enabled yet" card and hides the workspace — no crash. Save/test/pull/delete also detect the flag-off 404.
- Loading + error states throughout; 401 → "Sign in with an authorized owner or admin account.", 403 → "Your account cannot manage EMR connections for this organization." Empty state: "No EMRs connected yet. Add one above." No em-dash in any visible copy (verified by grep + the smoke test).

## Notes / concerns
- **Tenant ID is entered by the admin.** It is required by the shipped contract; a hospital admin may not know their tenant ID offhand. A later increment could resolve "my tenants" from membership and present a dropdown instead of a free-text field (backend endpoint needed).
- **SMART key material in the DOM.** For SMART Backend Services the page collects `privateKeyJwk`/`kid`/`alg` (the backend seals them). That private key lives in the textarea until save; it is never rendered back afterward (list omits it) and is not logged. The primary/self-service path is Token/API-key; SMART is the advanced path. Acceptable for owner-only admin use; flag it if you want SMART key entry moved to a paste-and-forget field.
- **Pulled bundle is PHI** shown as JSON — that is the intended "see real data flowing" tester. It is patient data, not secrets. LLM egress stays behind the existing BAA/R7 gate (unchanged); this is in-app viewing only.
- The page mirrors the admin console look via the same CSS tokens/components, but is a separate file (no sidebar; single-column). It is not linked from `admin/index.html` nav (would be a one-line add there later if desired) to keep this change conflict-free.
- Firebase compat scripts load from the gstatic CDN, same as `admin/index.html`; if unreachable the page still loads (init is try/catch-guarded) and shows the sign-in gate.
